# 博雅教育课程专项解析

生成日期：2026-08-26

本文件是阶段一报告的博雅课专项补充，先于任何线上操作使用。结论来自本地脱敏页面和前端脚本；真实响应、当前轮次和实时容量仍需在授权登录状态下只读核对。

## 1. 查询表单对应关系

博雅课页面位于 `#cvPublicCourse`，教学班类型是 `XGXK`。页面表单位于 `选课点击后.html:395-416`：

| 页面控件 | 取值 | 传入字段 | 作用 |
|---|---|---|---|
| `#public_sfct`（是否冲突） | `0` 不冲突；`1` 冲突；`2` 不筛选 | `checkConflict` | 让服务端按已有课程冲突状态筛选 |
| `#public_sfym`（是否已满） | `0` 未满；`1` 已满；`2` 不筛选 | `checkCapacity` | 让服务端按容量状态筛选 |
| `#public_xgxklb`（博雅课类别） | 类别代码，空值为不筛选 | `queryContent` 中的 `XGXKLBDM` | 博雅课程类别 |
| `#course_section`（课程板块，可由系统参数决定是否显示） | 字典 `KCBK` 中的代码 | `queryContent` 中的 `KCBK` | 课程板块 |
| `#publicSearch`（关键字） | 用户输入 | `queryContent` | 课程名称/课程号等搜索内容，具体字段由服务端解释 |

页面还明确提示：2024 级及以后学生应按“博雅课类别(2024)”选课；实际类别显示由页面字典/系统参数提供，不应从旧客户端硬编码。

## 2. 实际 query 的静态结构

`grablessons.js:3071-3151` 中，初次进入博雅课或修改筛选条件都会调用 `CVPublicCourse.listInit/listReload`，进而调用 `queryPublicCourse`。`grablessons.js:4346-4588` 的 `buildQueryTCParam` 会构造如下逻辑结构，下面的尖括号均为运行时状态，不是可用账号值：

```text
POST {BaseUrl}/sys/xsxkapp/elective/publicCourse.do
Headers: token = <sessionStorage.token>
Form field: querySetting = JSON string

querySetting = {
  "data": {
    "studentCode": <studentInfo.code>,
    "campus": <currentCampus.code>,
    "electiveBatchCode": <studentInfo.electiveBatch.code>,
    "isMajor": "1",
    "teachingClassType": "XGXK",
    "checkConflict": "0",        // 选择“不冲突”
    "checkCapacity": "0",         // 选择“未满”
    "queryContent": "XGXKLBDM:<类别>,KCBK:<板块>,<关键字>"
  },
  "pageSize": "10",
  "pageNumber": "0",
  "order": ""
}
```

精确的 `queryContent` 只包含已填写的条件，空类别、空板块和空关键字不会被强行写入。下拉框变化会重置博雅课页码为 0 并重新查询，见 `grablessons.js:5956-5998`。

`xsxkpub.js:102-110` 显示该请求使用 POST，并显式传入 `token` 请求头。`bh_utils.js:338-400` 没有覆盖 jQuery 默认的表单序列化设置，因此当前源码只能确认“提交 `querySetting` 字段的 AJAX 请求”；实际 Content-Type 和浏览器发送的 Cookie 应以授权 HAR 复核。

## 3. 查询结果如何判断“无冲突、未满”

服务端成功响应由 `grablessons.js:3085-3115` 消费，前端期待：

- `code == '1'`：读取 `totalCount` 和 `dataList`，分页并渲染列表；
- `dataList` 中的 `teachingClassID` 是后续选课所需的教学班标识；
- `isConflict`、`conflictDesc`：渲染 `[冲突]` 和说明；
- `isFull`：渲染 `[已满]`；
- `numberOfFirstVolunteer` 与 `classCapacity`：展示已选人数/班容量；首志愿人数达到容量时显示“人数已满”；
- `hasTest`、`capacitySuffix`、`limitGender`、男女容量/人数、`campus`、`teachCampus`：影响后续实验课、教材、性别容量和校区校验。

因此，查询条件应同时设置：

```text
是否冲突 = 不冲突（value=0）
是否已满 = 未满（value=0）
```

但这不是最终保证。容量和冲突会随服务端状态变化；而且 `buildPublicCourseListHtml` 主要把 `isFull/isConflict` 转成显示标记，公共课 `.cv-choice` 的点击入口 `grablessons.js:531-563` 明确做了冲突、轮次和校区检查，却没有像普通课程卡片点击路径那样单独用 `isFull` 再拦截。因此实际提交前必须再次确认当前行没有 `[已满]`/`[冲突]`，并最好刷新该教学班容量。

## 4. 登录状态下选择一门公共课的源码链路

### 4.1 登录/轮次状态

登录后的注册回调在 `loginInUserRegister.js:1-53`：成功时取服务端返回的学生编号和令牌，写入 `sessionStorage`，再由侧边栏读取学生信息和选课轮次。`sidebar.js:356-376` 把当前轮次写入 `studentInfo.electiveBatch`、`currentBatch` 和 `electiveIsOpen`，并根据轮次类型进入选课页面。

### 4.2 点击“选择”前

公共课选择事件在 `grablessons.js:531-563`：

1. 如果按钮被标记为禁用，直接返回。
2. 检查 `electiveIsOpen`；不确定时同步调用 `batchisopen.do`，参数含当前批次代码。
3. 调用 `checkIsConflict`，使用列表行的 `isConflict` 和当前轮次的冲突豁免开关。
4. 调用 `checkSfkxqSelect`，根据课程行的 `campus/teachCampus`、学生当前校区和轮次的跨校区/教学区开关，提示或阻止跨校区选择。
5. 通过后进入 `selectPublicCourse(e, 'public')`。

### 4.3 公共课确认与请求

`selectPublicCourse` 在 `grablessons.js:697-749`：

- 若有实验课程 `hasTest == '1'`，先进入实验课选择窗口；
- 若允许教材选择，先显示教材确认；
- 否则显示“确认选择”对话框；
- 最终由 `sureHandle` 调用 `buildAddVolunteerParam` 和 `addVolunteer`。

`buildAddVolunteerParam` 在 `grablessons.js:4596-4637` 中生成：

```text
addParam = {
  "data": {
    "operationType": "1",
    "studentCode": <studentInfo.code>,
    "electiveBatchCode": <studentInfo.electiveBatch.code>,
    "teachingClassId": <clicked row tcId>,
    "isMajor": "1",
    "campus": <currentCampus.code>,
    "teachingClassType": "XGXK",
    "needBook": <optional>,
    "testTeachingClassID": <optional>
  }
}
```

随后 `xsxkpub.js:142-150` 以 POST 调用：

```text
{BaseUrl}/sys/xsxkapp/elective/volunteer.do
Headers: token = <sessionStorage.token>
Form field: addParam = JSON string
```

本地 NNU 前端直接构造上述嵌套 JSON。公开 NJU/SZU 客户端对同名端点存在加密或额外字段变体，不能覆盖本地 NNU 证据。

### 4.4 结果确认

`volunteer.do` 返回 `code == '1'` 后，前端在 `xsxkpub.js:407-461` 轮询：

```text
POST {BaseUrl}/sys/xsxkapp/elective/studentstatus.do
Body: {"studentCode": <studentInfo.code>}
```

约每秒重试一次，最多约 10 次：

- `code == '1'`：显示添加成功，更新行状态、容量和已选数量；
- `code == '-1'`：显示服务端失败原因；
- 超时：显示稍后再试；
- 任一业务响应 `code == '302'` 或通用响应出现 `loginURL`：清理本地会话并回到入口页。

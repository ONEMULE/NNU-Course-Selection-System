# 阶段一：NNU 选课系统与公开源码静态解析

生成日期：2026-08-26

本报告只使用本地脱敏 HTML/JavaScript、已经收集的公开资料和公开仓库源码快照。没有登录、没有调用南师大线上接口，也没有运行第三方仓库中的自动化程序。

## 一、结论摘要

1. 本地页面是金智教育 WISEDU `XSXKAPP` 选课前端：页面配置直接指向 `https://xsxk.nnu.edu.cn:443/xsxkapp`，静态资源版本线索为 `1.8.1_TR13`，登录形态标记为 `ldap`。这属于本地快照直接证据。
2. 前端不是以现代框架打包的单体应用，而是服务端页面加 jQuery 模块组合：通用 AJAX、登录注册、学生/轮次初始化、课程列表、侧边栏、已选结果和退选日志分别由多个脚本承担。
3. 业务主链路已经可以静态还原：

   ```text
   SSO/register
       -> sessionStorage 保存 token、studentInfo、currentBatch 等状态
       -> initMenuControl 依据轮次和系统参数显示课程类型
       -> buildQueryTCParam 生成 querySetting
       -> recommended/program/public/queryCourse 查询课程
       -> 前端做开放、容量、性别、冲突、校区检查
       -> volunteer.do 提交添加/删除请求
       -> studentstatus.do 轮询异步处理结果
       -> 更新课程状态、容量和已选数量
   ```

4. `volunteer.do` 的第一响应不能直接等同于选课成功：前端在返回 `code == '1'` 后继续请求 `studentstatus.do`；轮询结果 `code == '1'` 才显示成功，`code == '-1'` 显示失败。
5. NNU 直接相关的公开源码主要证明 CAS/eHall/课表上下文，并不是本地选课前端的完整实现。其他学校的 WISEDU 客户端在端点命名、令牌头、`volunteer.do`、验证码路径和异步状态上有较强相似性，但部署差异必须单独验证。

## 三、本地前端结构

### 3.1 页面配置与脚本加载

`选课点击后/选课点击后.html:1662-1699` 直接给出：

- `BaseUrl = https://xsxk.nnu.edu.cn:443/xsxkapp`
- `resUrl = https://res.nnu.edu.cn/ver/1.8.1_TR13/products/jwfw/xsxkapp`
- `loginType = ldap`
- `pageType = grablessons`

脚本加载顺序体现了依赖关系：`bh_utils.js` 先提供 AJAX 和通用工具，随后加载登录注册、初始化、选课主模块、侧边栏、容量模块、退选日志、已选结果和公共请求包装模块。

### 3.3 前端状态

从 3 份脱敏资源目录中提取到 12 个 `sessionStorage` 键；统计和证据位置见 `session_storage_inventory.csv`。关键状态如下：

| 键 | 用途 | 读写特征 |
|---|---|---|
| `token` | 业务请求令牌 | 设置、读取、失效时删除；实际值未进入分析文件 |
| `studentInfo` | 学生代码、性别、校区、当前轮次等 | 频繁读取；注册成功或会话失效时更新/删除 |

| `teachingClassType` | 当前课程类别 | 切换标签时写入，查询/选课时读取 |
| `electiveIsOpen` | 当前轮次是否开放 | 操作前检查，不确定时同步请求 `batchisopen.do` |
| `sysParam` | 系统功能、菜单、教材和展示开关 | 主要读取 |
| `bookParam` | 教材是否需要/可选/可删除 | 初始化时写入，选课和教材交互时读取 |
| `campusList`、`dictionary` | 校区和字典显示数据 | 主要读取 |
| `celebrityFamous`、`copyright`、`isInitStep` | 页面展示或初始化标记 | 低频读取/写入 |

## 四、请求抽象与调用图

### 4.1 通用 AJAX 层

`bh_utils.js:338-400` 的 `BH_UTILS.doAjax`：

- 默认方法为 POST，传入数据对象和调用方提供的 headers；返回 JSON 结果的 Deferred Promise。
- 成功回调会解析字符串 JSON；如果响应中存在非空 `loginURL`，前端跳转到该地址。
- `401/403` 会记录异常；网络错误会弹出提示。

`bh_utils.js:410-470` 的 `doSyncAjax` 使用同步请求、`traditional=true`，但函数签名没有单独的 headers 参数。因此，是否携带令牌要结合具体调用和浏览器会话判断，不能只依据“同步”二字推断。

### 4.2 读取类请求

主要业务包装函数位于 `xsxkpub.js`、`indexBS.js`、`selectedcourseBS.js` 和 `departurelogBS.js`：

- 初始化：学生信息、选课批次、公共信息、字典、系统参数、在线人数。
- 课程查询：推荐、方案内/外、公选、通用全校课程查询。
- 详情和资格：教学班详情、课程方案、`canchoose.do`、实验课程。
- 结果：已选课程、选课数量、退选/操作日志、队列和落选提示。
- 容量：`teachingclass/capacity.do` 返回后更新“已选/容量/性别容量”显示。

大多数业务包装函数显式传入 `{"token": sessionStorage.token}`；批次、公共信息、系统参数、注册和自动登出等函数存在未显式传入 token 的调用。完整结构化清单见 `static_call_graph.csv` 和 `endpoint_inventory.csv`。

### 4.3 添加、删除和异步处理

添加链路由 `grablessons.js:866-1021`、`4596-4637` 和 `xsxkpub.js:142-150` 共同构成：

1. 点击课程卡片时检查轮次开放状态、`canOperate`、是否已选、容量、性别容量、课程冲突和跨校区/教学区规则。
2. `buildAddVolunteerParam` 从 `sessionStorage` 读取学生、批次、校区和教学班类型，构造 `addParam`。可选字段包括教材选择和实验教学班 ID。
3. POST `/sys/xsxkapp/elective/volunteer.do`。
4. 首次响应 `code == '1'` 后进入 `initProcessInterval`，继续 POST `/sys/xsxkapp/elective/studentstatus.do`。
5. 轮询每约 1 秒继续一次，最多约 10 次；最终 `1` 为成功，`-1` 为失败，超时则提示稍后重试。
6. 成功时更新课程卡片为“已选”，刷新容量，并重新查询已选课程数量；`302` 会清理令牌和学生状态并返回入口页。

删除链路在 `grablessons.js:2584-2637`：使用 `operationType=2` 的 `deleteParam` 调用 `deleteVolunteer.do`，接受后复用同一套状态轮询；成功时移除“已选”标记、刷新容量和数量。

### 4.4 卡片状态字段

`CVCourseCard` 使用的关键字段包括教学班 ID、课程号、教师、时间地点、班容量、首志愿人数、是否满员、是否冲突、是否已选、是否限制性别、男女容量/人数和是否在队列中。要特别区分：

- `numberOfFirstVolunteer < classCapacity` 用于显示可选容量提示；
- `isFull` 控制“人数已满”及点击拦截；
- `inQuene == '1'` 会把卡片设为不可操作并隐藏删除/已选显示；
- 重修类型有单独的容量豁免开关，不能简单套用普通课程规则。

### 6.3 目前最重要的实现差异

本地 NNU 前端在 `buildAddVolunteerParam` 中直接拼接嵌套 JSON，再交给 `addVolunteer`。公开 NJU 客户端对相似结构做了客户端变换，SZU 客户端还出现 `chooseVolunteer` 等额外字段。这说明“WISEDU 共用端点”与“当前 NNU 的确切线协议”是两个层次的问题；必须以 NNU 自有、已脱敏的授权 HAR 或浏览器 Network 记录为准。

## 七、当前结论边界与待确认项

已经直接确认：

- NNU 选课应用的页面主机、资源版本线索、登录类型标记和页面类型；
- 前端模块边界、课程类别映射、主要端点路径和 HTTP 方法；
- `sessionStorage` 状态键及其作用方向；
- 添加/删除请求在前端中的字段包装、异步轮询和 DOM 更新逻辑；
- 三份快照的结构状态和浏览器扩展噪声。

仍然不能从当前资料确认：

- NNU 当前服务端的真实响应 JSON 外壳及所有字段类型；
- 当前部署是否在网关或服务端要求某种额外的 `addParam` 变换；
- 令牌的生命周期、Cookie 属性、批次动态开关和在线人数限制；
- 课程列表的全部分页、排序和实验课程响应结构；
- 2026 年当前选课批次与页面快照时点是否一致。

## 八、下一阶段建议

只在获得明确授权和脱敏后进行：

1. 补充一次只读的、去除 Cookie/令牌/账号/课程个人信息的 HAR，核对 Content-Type、表单字段、响应 `code/msg/data/dataList` 和真实调用顺序。
2. 将登录后首页、课程列表、已选结果、退选日志和失败弹窗按时间线对应起来，补齐 `studentInfo/currentBatch/sysParam` 的字段字典；不保存真实值。
3. 对 `GreenTeodoro839/NJU-xk-helper`、`Weeye-hua/SZU-Course-Help` 和 `HansZ8/BIT-XK-WISEDU` 做文件级人工对照，重点只研究请求封装和状态机，不执行自动抢课逻辑。
4. 用新的静态快照复核资源版本、标签可见性和端点命名是否变化，再决定是否进入接口兼容性分析。

当前待采集任务见 `04_提取分析/后续采集清单.md`。

# 博雅课自动化脚本说明

脚本位置：选课/05_工具/nnu_boya_automation.py

## 功能边界

脚本固定只查询：

- 仙林校区：campus=2
- 仙林新北：campus=4

每次查询都使用：

- teachingClassType=XGXK
- checkConflict=0（不冲突）
- checkCapacity=0（未满）
- 不限定课程类别、课程板块或关键词

脚本默认只读。每次启动都会创建全新的可见浏览器会话，由用户本人完成验证码/人机认证；本次运行结束后不保留 Cookie、sessionStorage 或浏览器 profile。脚本可选地从 Windows 凭据管理器读取学号和密码并填入登录框，但只在当前进程内短暂使用，不打印、不写入源码或普通配置文件，不导出 token，也不绕过验证码或自动点击登录。

## 安装

在仓库根目录执行：

~~~powershell
python -m pip install -r 选课/05_工具/requirements-automation.txt
python -m playwright install chromium
~~~

首次使用自动填充时，在本机终端执行一次：

~~~powershell
python 选课/05_工具/nnu_boya_automation.py --setup-credentials
~~~

命令会隐藏输入密码，并将学号/密码保存到 Windows 凭据管理器；密码不会出现在命令行参数、脚本、日志或 Git 中。之后每次运行都会打开一个全新的可见浏览器窗口，自动填入 `#loginName` 和 `#loginPwd`，停在登录入口等待你填写验证码、完成人机认证并点击登录。再次启动时仍需重新认证，不复用上次 Cookie 或登录态。

本次不想自动填充时可使用：

~~~powershell
python 选课/05_工具/nnu_boya_automation.py --no-auto-fill
~~~

删除已保存凭据：

~~~powershell
python 选课/05_工具/nnu_boya_automation.py --clear-credentials
~~~

## 只读查询

~~~powershell
python 选课/05_工具/nnu_boya_automation.py
~~~

持续查询（默认每 30 秒一次；脚本会尊重最小请求间隔）：

~~~powershell
python 选课/05_工具/nnu_boya_automation.py --watch --output 选课/05_工具/.runtime/latest.json
~~~

只持续轮询仙林校区；当当前轮次已选的非实验课程少于 4 门时，发现服务端确认“无冲突 + 未满”的博雅课就自动提交，达到 4 门后退出：

~~~powershell
python 选课/05_工具/nnu_boya_automation.py --watch --auto-select --yes --need-book 0
~~~

`--auto-select` 是显式提交开关，只查询仙林校区（campus=2），并按页面口径通过 `courseResult.do` 统计当前轮次已选的非实验课程数量。少于 4 门时，脚本按服务端返回顺序尝试第一门尚未选中的安全候选；提交前仍会重新查询、刷新容量、确认轮次开放，并检查实验课/教材条件。该模式必须同时使用 `--yes` 和 `--need-book 0/1`，因为它会在全部预检通过后直接调用提交接口。达到 4 门后脚本退出；没有候选时会一直轮询到你手动停止。

输出只包含课程目录字段和查询统计，不包含学生编号、密码、Cookie、token 或原始服务响应。

## 受控提交

必须指定精确教学班 ID，并显式开启 --submit。默认还会在终端要求再次输入该教学班 ID：

~~~powershell
python 选课/05_工具/nnu_boya_automation.py --course-id 目标教学班ID --submit
~~~

无人值守轮询可以显式加 --yes，但仍必须保留精确教学班 ID：

~~~powershell
python 选课/05_工具/nnu_boya_automation.py --watch --course-id 目标教学班ID --submit --yes
~~~

提交前脚本会：

1. 通过页面原生校区菜单对齐目标校区；
2. 对该校区重新执行“不冲突 + 未满”查询；
3. 确认目标教学班唯一存在且 isConflict=0/isFull=0；
4. 查询教学班详情并刷新容量；
5. 确认轮次开放；
6. 才调用 volunteer.do，随后最多轮询 10 次 studentstatus.do。

脚本不会自动重试 volunteer.do。遇到教材选择权限不明确、校区切换失败、登录态失效或容量/冲突状态变化时，脚本直接停止，由用户回到页面人工判断。若课程需要实验教学班，必须额外提供明确的 --test-teaching-class-id；脚本会调用 testCourse.do 重新核验该实验班的冲突、限制和容量，不会替用户猜选实验班。

## 与源码/同类项目的对应

NNU 本地脱敏前端中的调用关系是：

~~~text
buildQueryTCParam
  -> publicCourse.do
buildAddVolunteerParam
  -> volunteer.do
volunteer.do code=1
  -> studentstatus.do
~~~

脚本沿用本地 NNU 页面确认过的字段和 form-urlencoded 外壳；其他学校公开项目中的账号密码写死、Cookie 拼接和验证码处理仅作比较证据，没有复制到本实现。

API 请求会统一挂在 NNU 实际应用上下文 `/xsxkapp` 下，即形如
`https://xsxk.nnu.edu.cn/xsxkapp/sys/xsxkapp/...`；不能把 `/sys/xsxkapp/...`
直接按站点根路径发送。`courseResult.do` 和容量查询的缓存时间戳也按页面原生
请求放在 URL 的 query 开头。若日志出现 401，先确认页面地址仍在
`/xsxkapp/sys/xsxkapp/*default/grablessons.do`，再检查登录态是否已过期。

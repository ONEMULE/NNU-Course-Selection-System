# 博雅课自动化脚本说明

脚本位置：选课/05_工具/nnu_boya_automation.py

## 功能边界

脚本固定只查询：

- 仙林校区：campus=2
- 仙林新北：campus=4

博雅课查询/自动选课使用：

- teachingClassType=XGXK
- 监控轮次不限定 checkConflict/checkCapacity，以读取全部博雅课并计算网络课人数增量
- 候选必须在本地明确满足 isConflict=0、isFull=0、isChoose!=1
- 提交预检重新使用 checkConflict=0、checkCapacity=0，并刷新详情与容量
- 模块互斥只认 publicCourseTypeName2（博雅课类型 2024）

全校课程采集使用页面的 QXKC 分支；它向 `queryCourse.do` 发送
`teachingClassType=QXKC`，不附带博雅查询的 `checkConflict`/
`checkCapacity` 字段。

脚本默认只读。每次启动都会创建全新的可见浏览器会话，由用户本人完成验证码/人机认证；本次运行结束后不保留 Cookie、sessionStorage 或浏览器 profile。脚本可选地从 Windows 凭据管理器读取学号和密码并填入登录框，但只在当前进程内短暂使用，不打印、不写入源码或普通配置文件，不导出 token，也不绕过验证码或自动点击登录。

## 安装

在仓库根目录执行：

~~~powershell
python -m pip install -r 选课/05_工具/requirements-automation.txt
python -m playwright install chromium
~~~

首次使用自动填充时，在本机终端执行一次：

~~~powershell
python 选课/05_工具/nnu_boya_automation.py --setup-credentials
~~~

命令会隐藏输入密码，并将学号/密码保存到 Windows 凭据管理器；密码不会出现在命令行参数、脚本、日志或 Git 中。之后每次运行都会打开一个全新的可见浏览器窗口，自动填入 `#loginName` 和 `#loginPwd`，停在登录入口等待你填写验证码、完成人机认证并点击登录。再次启动时仍需重新认证，不复用上次 Cookie 或登录态。

本次不想自动填充时可使用：

~~~powershell
python 选课/05_工具/nnu_boya_automation.py --no-auto-fill
~~~

删除已保存凭据：

~~~powershell
python 选课/05_工具/nnu_boya_automation.py --clear-credentials
~~~

## 只读查询

~~~powershell
python 选课/05_工具/nnu_boya_automation.py
~~~

持续查询（自动模式默认每 0.1 秒开始下一轮；分页请求仍遵守独立请求间隔，watch 模式使用固定屏幕 TUI）：

~~~powershell
python 选课/05_工具/nnu_boya_automation.py --watch --output 选课/05_工具/.runtime/latest.json
~~~

也可以在可见 Windows 终端中直接运行脚本：

~~~powershell
python 选课/05_工具/nnu_boya_automation.py
~~~

无操作参数时会先进入鼠标配置 TUI，并预加载“自动选课”完整预设；确认模式、校区、目标课程和安全规则后，点击“应用并启动”才打开登录浏览器。若只想查询，可在配置页点击“模式 W｜只监控”。

只持续轮询仙林校区；按照固定优先级和 2024 模块互斥规则选课，目标为 **5 门**。5 门课程的 2024 模块必须互不相同，必须包含线下《中国民歌》，且网络课最多 2 门、线下课至少 3 门。学分只在 TUI 中展示，不作为额外的停止条件。达到目标后停止自动提交，并进入 `DONE_HOLD` 保留浏览器供人工检查，直到用户明确退出：

~~~powershell
python 选课/05_工具/nnu_boya_automation.py --watch --auto-select --yes --need-book 0
~~~

`--auto-select` 是显式提交开关，只查询仙林校区（campus=2），并通过 `courseResult.do` 逐行识别当前轮次已选课程：排除 `isTest=1` 实验行，只统计明确标记为 `teachingClassType=XGXK`、带 `publicCourseType*` 或明确显示博雅/校公选的课程。脚本会先轮询 `batchisopen.do`，服务端未确认开放时保持 `ARMED`，即使页面已提前展示课程列表也禁止提交；开放后才执行 `publicCourse.do` 查询。

自动顺序为：①线下《中国民歌》（艺术鉴赏与审美体验）；②网络《创新创业基础》，不可用时尝试同模块《智能文明》（创新与创业只选一门）；③网络《揭秘大气污染》（身心健康与生命关怀）；④网络《航空航天概论》（数理基础与科学技术）；⑤从尚未占用的其他 2024 模块中选线下兜底；⑥在仍有网络预算时按人数热度选网络兜底。《航空航天概论》仅在前三个指定目标已处理且模块未占用时尝试。5 门中网络候选最多 2 门；当剩余名额必须用于凑足 3 门线下课时，网络候选会被屏蔽。网络兜底按“本轮人数增量 → 拥挤率 → 已选人数”降序排列。只要《中国民歌》尚未成功，脚本就为它保留名额，绝不会用其他课程占掉该模块。若 `courseResult.do` 省略 2024 模块或线上/线下字段，脚本会按同轮 `publicCourse.do` 的教学班 ID 回填；仍无法确认时停止，不使用猜测。

每次提交前仍会重新执行无冲突/未满查询、刷新详情和容量、再次确认轮次开放，并检查实验课/教材条件。查询、容量、轮次、状态等只读/幂等请求默认 15 秒超时，超时、断网、429 和常见 5xx 最多进行 3 次指数退避重试。`volunteer.do` 永不自动重发：如果写请求本身超时、断网、5xx 或登录态异常，脚本进入只读核验，只查询 `courseResult.do`/`studentstatus.do`；10 次仍不能确认时进入 `VERIFY_HOLD` 并保留浏览器，避免重复提交。该模式必须同时使用 `--yes` 和 `--need-book 0/1`。只有达到 5 门、5 个 2024 模块互异、包含《中国民歌》、网络不超过 2 门且线下至少 3 门时才停止自动提交；已选学分只作为 TUI 的信息展示。没有满足预算的候选时一直轮询到你手动停止。

本地 NNU 前端源码只观察到登录成功后把 `data.token` 写入 `sessionStorage.token`，没有发现固定 TTL、refresh token、refresh 接口或可提前读取的过期时间。官方页面在会话失效时主要通过 `code=302`、`loginURL` 或 HTTP 401/403 清除 token 并回登录页。因此脚本不猜测“token 能活几分钟”，而是按真实失效信号进入 `REAUTH`：在同一个可见浏览器中清理旧 sessionStorage 登录态、回登录入口、重新从 Windows 凭据管理器填入学号密码，等待本人完成验证码/人机认证；成功后重读学生/轮次/校区上下文，清空旧的人数增量基线并继续原来的循环。`volunteer.do` 写请求期间若恰好发生会话异常，同样不会自动重发，只会在重新认证后核验是否已经选中。

运行时间建议：在南京时间开放前 3–5 分钟启动并完成登录（例如 16:55–16:57），不要提前很久登录。这样能给人工验证码留出余量，又减少 token 在开放前失效的机会；若运行中出现真实失效信号，脚本会显示 `REAUTH` 并在同一浏览器等待本人再次认证。

TUI 只刷新当前屏幕，不把每轮状态追加到终端；画面会显示运行时长、轮询次数、登录态、浏览器当前页面校区、脚本实际请求校区、实际/期望教学班类型、目标选择器、2024 模块规则、网络/线下数量预算、教材选项、轮询/请求/分页/超时参数、博雅课程进度、全部网络课监控数、人数增速前三名、当前下一候选、提交统计和最近事件。命令行提供初始值，配置页可在启动前调整，便于审计启动配置和实际请求范围。人数快照每轮整体替换，事件队列固定最多 7 条，不会随着轮询时长增长。需要纯文本日志时可添加 `--plain-output`。

watch 模式启动后先显示中文可操作配置页：Windows 控制台支持鼠标点击配置行、滚轮调整数值；“模式 A｜自动选课”和“模式 W｜只监控”是互斥单选按钮，界面用 `[*]` 标出当前选中项，点击模式按钮会加载该模式的完整预设。“自动选课”预设为 0.1 秒轮询、0.5 秒分页请求间隔、每页 50 条、最多 50 页、登录等待 300 秒、凭据自动填充、教材不订、快照关闭，并锁定请求校区为仙林（2）；“只监控”使用 1 秒轮询，校区为仙林（2）和仙林新北（4），不调用提交。预设加载后，教材、轮询/请求间隔、分页、登录等待、登录填充和快照等普通参数仍可通过中文行按钮或滚轮调整；“恢复当前模式预设”或 `R` 可重新加载整套默认值。安全规则、自动模式校区和自动确认显示为锁定项，验证码/人机认证始终人工完成。

目标行可输入 `auto`、`watch`、`id:<教学班ID>`、`number:<课程号>` 或 `name:<课程名>`，点击“应用并启动”后才打开登录浏览器；`Q`/`Esc` 取消，回车或键盘 `A` 应用。实验教学班 ID 只在明确目标提交模式下可编辑，自动博雅模式不会替用户猜选实验班。

输出只包含课程目录字段和查询统计，不包含学生编号、密码、Cookie、token 或原始服务响应。

## 全校课程与已选课程采集

脚本另提供只读采集模式。它沿用本地前端 `QXKC` 页签的请求：

```text
QXKC -> POST /sys/xsxkapp/elective/queryCourse.do
       querySetting.data.teachingClassType = QXKC
```

`queryCourse.do` 返回的是当前选课批次的课程汇总对象，教学班放在 `tcList` 中。
脚本会按仙林（2）和仙林新北（4）两个校区上下文分页请求、按教学班 ID 去重，并输出：

- `all_open_courses.json`：保留课程汇总和教学班层级，附带容量、冲突、已选和当前可操作标记；`selectableNow` 是依据接口状态计算的保守提示，不替代提交前复核；
- `all_open_courses.csv`：展开为一行一个教学班，便于 Excel 筛选；
- `selected_courses.json`：从 `courseResult.do` 整理当前批次已选理论课和实验课关联；
- `selected_courses.csv`：当前已选记录的平面表格。

运行示例：

```powershell
python 选课/05_工具/nnu_boya_automation.py --collect-open-courses
python 选课/05_工具/nnu_boya_automation.py --collect-selected-courses
python 选课/05_工具/nnu_boya_automation.py --collect-open-courses --collect-selected-courses --export-dir 选课/05_工具/.runtime
```

可用 `--school-keyword`、`--school-category`（`XGXKLBDM`）和 `--school-unit`（`KKDWDM`）复刻全校课程页筛选。采集模式是一次性只读任务，不能和 `--watch`、`--submit`、`--auto-select` 或 `--output` 混用；结果目录默认被 Git 忽略，因为已选课程信息属于个人数据。

## 受控提交

必须指定精确教学班 ID，并显式开启 --submit。默认还会在终端要求再次输入该教学班 ID：

~~~powershell
python 选课/05_工具/nnu_boya_automation.py --course-id 目标教学班ID --submit
~~~

无人值守轮询可以显式加 --yes，但仍必须保留精确教学班 ID：

~~~powershell
python 选课/05_工具/nnu_boya_automation.py --watch --course-id 目标教学班ID --submit --yes
~~~

提交前脚本会：

1. 通过页面原生校区菜单对齐目标校区；
2. 对该校区重新执行“不冲突 + 未满”查询；
3. 确认目标教学班唯一存在且 isConflict=0/isFull=0；
4. 查询教学班详情并刷新容量；
5. 再次确认轮次开放（自动模式在候选查询前还设有一层 `batchisopen.do` 武装闸门）；
6. 才调用 volunteer.do，随后最多轮询 10 次 studentstatus.do。

明确目标提交模式和自动博雅模式都不会自动重试 `volunteer.do`。自动博雅模式遇到服务端明确拒绝时会换下一候选；只有能确认“服务端明确拒绝”时才继续。传输层结果不确定时只读核验，仍无法确认则保留浏览器人工处理。一般查询过程中遇到 token 失效会原地 `REAUTH` 后继续，不需要重启脚本；若重新认证本身超时，则保留浏览器等待人工处理。遇到教材选择权限不明确、校区切换失败或容量/冲突状态变化时，脚本拒绝该次提交；若课程需要实验教学班，必须额外提供明确的 `--test-teaching-class-id`，自动博雅模式不会替用户猜选实验班。

## 与源码/同类项目的对应

NNU 本地脱敏前端中的调用关系是：

~~~text
buildQueryTCParam
  -> publicCourse.do
buildAddVolunteerParam
  -> volunteer.do
volunteer.do code=1
  -> studentstatus.do
~~~

脚本沿用本地 NNU 页面确认过的字段和 form-urlencoded 外壳；其他学校公开项目中的账号密码写死、Cookie 拼接和验证码处理仅作比较证据，没有复制到本实现。

API 请求会统一挂在 NNU 实际应用上下文 `/xsxkapp` 下，即形如
`https://xsxk.nnu.edu.cn/xsxkapp/sys/xsxkapp/...`；不能把 `/sys/xsxkapp/...`
直接按站点根路径发送。`courseResult.do` 和容量查询的缓存时间戳也按页面原生
请求放在 URL 的 query 开头。若日志出现 401，先确认页面地址仍在
`/xsxkapp/sys/xsxkapp/*default/grablessons.do`，再检查登录态是否已过期。
